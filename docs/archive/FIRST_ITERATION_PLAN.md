## 一句話總結

第一輪的目標不是做成完整 App，也不是把所有功能重寫，而是：

> 把它收斂成一個本機優先、主流程穩定、資料可信的訓練記錄工具。

---

## 第一輪核心目標

這一輪只追兩件事：

### 1. 主流程更穩

也就是：

```text
打開
  → 開始記錄
  → 記完一組
  → 結束訓練
  → 資料保留下來
```

### 2. 歷史資料更可信

也就是：

- 不再依賴每次手動匯入
- 歷史資料以本機延續為主
- 匯出保留，但不再是主流程依賴

---

## 第一輪不追求的事

這一輪先不要追：

- Android 包裝
- 大型 UI 改版
- 新增大量功能
- 完整雲端同步
- 外觀 / 穿搭模組整合
- 高階 AI / 推薦系統

原因很簡單：

- 主流程還沒完全穩
- 資料模型還沒完全收斂
- 現在擴功能只會把複雜度再往上推

---

## 第一輪功能取捨

### 保留為核心

- 今日課表
- 每組重量 / 次數記錄
- 基本 rest timer
- 上次訓練資料提示
- `結束訓練`
- 歷史資料保留
- 匯出功能
- 基本自訂動作

### 弱化但先不刪

- 分析面板
- PR 趨勢
- 月報

這些可以先保留存在，但不是第一輪判斷成功與否的核心。

### 降級角色

- 匯入 markdown

之後它的角色應該是：

- 舊版資料遷移
- 備份還原
- 低頻工具功能

不再是日常訓練入口。

### 明確先不碰

- GitHub Sync 優化
- 體態照片整合
- 穿搭 / 髮型 / 眼鏡追蹤
- Android App 外殼

---

## 第一輪重構順序

### Step 1：先穩住資料主線

第一個要穩住的是這條鏈：

```text
記錄 sets
  → 結束訓練
  → 保存歷史
  → 重新打開仍可接續
  → 需要時再匯出
```

這是整個產品最核心的生命線。

如果這條線不穩，其他功能都沒有意義。

#### 這一步的重點

- 確認日常流程不依賴每次匯入
- 明確本機歷史的角色
- 明確 `sets` 與歷史資料的關係

---

### Step 2：整理動作名稱與 variant 映射

目前很多隱藏 bug 可能都來自這裡。

要先釐清：

- UI 主名稱
- 真正儲存名稱
- 歷史名稱
- 分析名稱

需要先建立一致規則，否則會一直出現：

- 上次資料抓錯
- 分析漏算
- PR 錯位

---

### Step 3：簡化並明確 rest timer 規則

第一輪不需要追求很聰明，只需要做到：

- 什麼時候保存
- 什麼時候放棄
- 什麼時候重新開始

規則清楚，比功能複雜更重要。

---

### Step 4：整理匯出與歷史讀取邏輯

因為匯出會保留，所以這一輪仍然要確保：

- 匯出格式穩定
- 歷史讀取規則穩定
- 不會一改欄位就連帶壞掉整個分析鏈

但重點會從「每次都要匯入」改成：

- `匯出` 是備份
- `讀歷史` 主要來自本機

---

### Step 5：最後才整理程式結構

像這些事情要做，但排在後面：

- 拆函式
- 分類 render 邏輯
- 分離資料層與 UI 層
- 拆出多檔案結構

原因不是它不重要，而是：

- 先修資料與主流程比較值錢
- 太早大重構很容易把現有功能一起打散

---

## 第一輪優先級

### P0：一定先做

- 日常流程不再依賴每次匯入
- `結束訓練` 正確保存
- 本機歷史可延續
- 匯出功能保留可用
- 動作名稱 / 變體映射規則清楚

### P1：接著處理

- 上次紀錄提示穩定
- rest timer 規則穩定
- 自訂動作不明顯破壞主流程
- 清除當日 / 清除暫存不殘留

### P2：主流程穩後再整理

- 月報
- 分析
- PR 圖
- GitHub Sync

---

## 第一輪驗證順序

這一輪不應該做完再回頭想怎麼測，而應該一路配合這個順序驗證：

### 驗證 1：標準訓練流程

```text
打開
  → 記錄多組
  → 結束訓練
  → 再打開
  → 確認歷史仍在
```

### 驗證 2：匯出功能

```text
完成訓練
  → 匯出
  → 檢查內容格式
```

### 驗證 3：上次紀錄提示

```text
有歷史資料
  → 再進入相同 day
  → 檢查 placeholder 與參考值
```

### 驗證 4：variant / rest / 自訂動作

這些屬於高風險轉場，應該在主流程穩後補測。

---

## 第一輪成功標準

第一輪不需要做到產品很完整，只要做到下面幾點，就算成功：

### 成功標準 1

你不需要每次先匯入訓練紀錄才能開始使用。

### 成功標準 2

完成訓練後，資料會可靠地留在本機歷史中。

### 成功標準 3

匯出仍然可用，作為備份與搬移工具。

### 成功標準 4

最常用的訓練記錄流程，比現在更穩、更短、更少意外。

## 第一輪之後才做的事

當第一輪完成後，下一輪才適合考慮：

- 結構化歷史資料正式化
- 分析重新整理
- 體重 / 體脂 / 腰圍接入
- 體態照片模組
- Android 包裝

再往後才是：

- 穿搭 / 髮型 / 眼鏡功能
- 外觀月報
- 更進階推薦與分析

## 實際執行建議

如果真的開始做，建議節奏不要用「功能大改版」，而是用這種方式：

### Round 1A

- 先把主流程資料保存方向定下來

### Round 1B

- 修動作命名與 variant 映射

### Round 1C

- 修 rest timer 與高風險轉場

### Round 1D

- 整理匯出 / 歷史讀取

### Round 1E

- 最後再清理程式結構

這樣比較不容易一次動太多東西。
